Lesson 1 · 5 minutes

Why an agent burns tokens when it uses MCP

By the end of this lesson you can look at an agent's MCP setup and point to the two places its tokens go.

Objective O1: explain where MCP token cost comes from About 5 minutes
Why this matters for you

Every MCP server you connect to an agent has a price. Knowing where it comes from tells you what to cut.

Warm-up 30 sec

Recall

When an agent sends a request to the model, what is in it besides your latest message?

Check your answer

The system prompt, the conversation so far, and a description of every tool it may call. All of it is counted in tokens. That last item is today's subject.

Cost 1: paid before you type 1.5 min

You connect five MCP servers to your agent and type hi. No tool runs. Here is what the model reads anyway, for every tool on every server:

gdrive.getDocument
  Description: Retrieves a document from Google Drive
  Parameters:
    documentId (required, string): the ID of the document
  Returns: document object with title, body, metadata

One of these is small. Now add them up, using Anthropic's own five-server setup:

ServerToolsTokens
GitHub35~26K
Slack11~21K
Sentry5~3K
Grafana5~3K
Splunk2~2K
Total58~55K

Your hi is one token or two. The request carrying it is about 55,000.

Each of those descriptions is a tool definition: the name, description and parameter schema that tell the model a tool exists and how to call it. Most MCP clients load all of them into context upfront (Anthropic, "Code execution with MCP"), which is how 58 tools use about 55K tokens "before the conversation even starts" (Anthropic, "Advanced tool use").

Why this works

The model has no memory of your servers. It can only pick a tool it can read about in the current request, so the client includes the definitions in every request, whether or not a tool gets used.

A common mix-up

"MCP only costs tokens when a tool is called." It feels right, because an API you never call is free. But the table above was the bill for typing hi.

Check yourself

An agent has four MCP servers connected. You ask it "what is 2 + 2?" and it answers without calling a tool. Which definitions did the model read?

Show the answer

Every definition.

Cost 2: paid for data passing through 1.5 min

Now the agent does call tools. You ask: "Download my meeting transcript from Google Drive and attach it to the Salesforce lead." Trace it:

  1. The model calls gdrive.getDocument.
  2. The full transcript comes back into the model's context. Copy 1.
  3. The model calls salesforce.updateRecord, and to do so it writes the full transcript out again as the argument. Copy 2.

What came back in step 2 is a tool result, and here it is an intermediate one: data the model only needed to hand to the next tool. Anthropic's write-up of this exact case says "every intermediate result must pass through the model", and that for a 2-hour sales meeting this "could mean processing an additional 50,000 tokens" (Anthropic, "Code execution with MCP").

Why this works

With direct tool calls, tools cannot talk to each other. The model is the only pipe between them, so anything moving from tool A to tool B is read as input tokens and then generated again as output tokens.

Check yourself

An agent calls a fetch_logs MCP tool to find one error line. The tool returns the whole 10 MB log. What does the model take in?

Show the answer

The whole log (Anthropic, "Advanced tool use").

Worked example and practice 1 min

Worked example

An agent has the five servers from the table. It is asked to copy a 50,000-token transcript from Drive to Salesforce. Where do the tokens go?

  1. Definitions: about 55K, loaded before the task starts.
  2. Result in: the transcript arrives as a tool result, 50K.
  3. Result out: the model rewrites it as an argument, another 50K.

Roughly 155K tokens, and the instruction itself was one sentence.

Your turn

Your agent has one Postgres MCP server with three tools. It runs SELECT * FROM orders, gets 5,000 rows back, and reports how many failed. Which of the two costs dominates, and what one change to the query shrinks it?

Show a solution

Cost 2. Three definitions are cheap; 5,000 rows as a tool result are not. Have the database do the work: SELECT COUNT(*) FROM orders WHERE status = 'failed' returns one number, so one number enters the context.

Summary

  • Tool definitions are loaded upfront: you pay for every connected tool, used or not.
  • Tool results enter the context in full, and data moved between tools is paid for twice.
  • Neither cost depends on how long your own message is.

Say it in your own words: why does typing "hi" to an agent with five MCP servers cost tens of thousands of tokens?
