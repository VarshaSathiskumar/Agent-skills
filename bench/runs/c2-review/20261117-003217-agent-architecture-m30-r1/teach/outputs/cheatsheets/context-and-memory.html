Context and memory in an agent

Cheat sheet for lesson 1 (objective O3)

Where information can live

PlaceWhat goes thereHow it gets to the model
Context windowSystem prompt and rules, tool definitions, the message history, tool resultsSent with every model call
Saved records (notes)Per-student, lasting facts: training, preferencesProgram loads at session start; save_note writes
Manual chunks (retrieval)Large reference text, needed occasionallysearch_manuals returns the top few chunks
Live toolsFacts that change: calendar slots, machine statusTool call when needed

Rules of thumb

  • The model sees only the current call's input; nothing carries over unless the program puts it there.
  • Every call re-sends the whole history, so total input tokens are the sum of all calls, not the last one.
  • More context is not better: recall degrades as it grows (context rot), and you pay for every token on every call.
  • Clear old tool results in occasional large batches (clearing breaks a cached prefix).
  • Training status and other access facts are written by the program from the sign-off record, never from chat; the booking tool re-checks.
  • Cap or summarize saved notes; a loaded record counts against the window.

Worked numbers (illustrative)

Call inputs 830 + 1,070 + 2,610 + 2,710 = 7,220 tokens. Pasting a 60,000-token manual over 4 calls = 240,000 tokens; retrieving 1,500 per call = 6,000.
