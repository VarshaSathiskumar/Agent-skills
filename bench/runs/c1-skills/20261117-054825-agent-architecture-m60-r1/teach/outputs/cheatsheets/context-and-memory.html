Context and memory: one page

From lesson 1. The model is blank at every call; memory is what your program puts back.

WhereWhat it holdsLastsCost
System promptShort rules that apply to every callEvery callResent every step
Message historyQuestions, model requests, tool resultsOne sessionGrows each step; big results paid for again at every later call
Summary (compaction)Decisions and open problems from a long chatRest of the sessionOne summary call; details can be lost
NotesShort durable facts about one studentBetween sessionsRead in at session start
RetrievalPrepared manual chunks, searched on demandPermanent storeOnly the few returned pieces enter the window
Fresh tool callFast-changing data, such as the calendarNot storedResult enters the window when asked

Rules of thumb

  • Cost of a tool result = its size x the number of calls after it.
  • More context is not better: recall drops as the window fills (context rot).
  • Save facts that change decisions; do not save transcripts or things a tool can look up.
  • Do not rely on a summary for safety-critical facts.
