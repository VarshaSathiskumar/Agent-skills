Context and memory in an agent

By the end of this lesson you can say, for any piece of information in the makerspace assistant, whether it lives in the context window, in saved notes, or in a manual that is searched on demand.

Objective O3: context and memory in an agent About 10 minutes
Why this matters for you

Your assistant must answer from long machine manuals and remember each student's training status between visits. Those are two different memory problems, and the budget makes a third one matter: everything in context is paid for on every step.

Warm-up 1 min

Recall

In the agent loop, the model asks for an action and the action is carried out. What happens to the result, and when does the loop stop?

Check your answer

The result goes back to the model, which decides the next step; it repeats until the model decides it is done. Today's question is where that result goes, and how long it stays there.

The context window 3 min

A student asks: "Can I use the laser cutter on Friday at 3?" Here is what the model is given at each step of the loop:

Step 1 input: [instructions] [tool list] [question]
              -> model asks: check_calendar("laser", "Fri 15:00")
Step 2 input: [instructions] [tool list] [question] [call 1] [result 1]
              -> model asks: get_training_status("student_42")
Step 3 input: [instructions] [tool list] [question] [call 1] [result 1] [call 2] [result 2]
              -> model writes the answer

Nothing is stored inside the model between steps. Each step, the program sends the whole growing pile again, and the model reads it from the top. If a tool returns a 40-page manual in step 2, those pages ride along in every later step too.

That pile has a name: the context, the set of tokens included when the model is sampled, and the context window is the limit on how many tokens fit in it (Anthropic, effective context engineering).

Why this works

The model only "knows" what is in its current input, so the program has to re-send everything it wants remembered. That makes context both the agent's working memory and a running cost: more tokens per step means a bigger bill, and Anthropic notes that recall gets worse as the context grows ("context rot").

Check yourself

At step 5, the assistant needs a fact that the calendar tool returned at step 1. Why can the model still use it?

Notes: memory between sessions 2 min

On Monday, student 42 finishes laser training. The session ends and the context is thrown away. On Thursday she returns and the new context starts empty: the assistant has never heard of her. Now suppose that at the end of Monday the assistant calls a tool:

write_note("student_42", "Laser training complete 2026-11-16")

On Thursday, step 1 loads that note into the new context, and the assistant can book her immediately.

Writing facts to storage outside the context window, and reading them back later, is the pattern Anthropic calls structured note-taking, or agentic memory; a to-do list or a NOTES.md file are examples (Anthropic).

Why this works

Context lasts one session, but a file or database row outlasts it. The agent carries across sessions only what it explicitly saved, and it pays tokens only for notes it loads.

A common mix-up

"The assistant remembers me from last time." It is tempting because chat apps feel that way. In your design, nothing carries over unless a note was written and then loaded.

Retrieval: finding the right page 3 min

A student asks: "What speed should I cut 3 mm acrylic at?" The laser manual has 300 pages. Putting it all in context would cost tokens at every step and bury the answer. Instead, the assistant has a tool:

search_manual("laser acrylic 3 mm speed")
  -> returns: [page 87: "Acrylic settings table"]  (a few hundred tokens)

Only that page enters the context. The assistant answers from it and cites page 87. If page 87 is not enough, it searches again with different words.

Fetching only the needed information at the moment it is needed, using a tool, is just-in-time retrieval. The agent keeps lightweight pointers (file paths, stored queries, links) and loads the data at run time (Anthropic).

Why this works

Only a small slice is paid for and read, so cost stays low and the model is less distracted. The trade-off is that the answer is only as good as the search: if it returns the wrong page, the model never sees the right one.

Check yourself

The search returns the page for the laser's cleaning schedule instead of cutting speeds. What is the likely result?

Worked example and practice 2 min

Worked example

Where does "the vinyl cutter's blade depth setting for cardstock" belong?

  1. Is it about one student? No, so it is not a per-student note.
  2. Does it already exist in a manual? Yes, so retrieval can find it; do not copy it into notes.
  3. Is it needed every step? No, so do not preload it. Retrieve it when asked, and it sits in context only for that session.
Your turn

Show a solution

Summary 1 min

  • Context is everything re-sent to the model each step; it grows and costs tokens every time.
  • Notes carry durable facts across sessions, but only if written and loaded.
  • Retrieval pulls the one needed page in at the moment of need.
