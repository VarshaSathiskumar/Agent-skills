Context and memory: what an agent keeps, and what it has to save

By the end of this lesson you can say, for your makerspace assistant, what sits in its context, what is lost when a session ends, and how notes and retrieval fix both problems.

Objective O3: context and memory in an agent About 10 minutes
Why this matters for you

Your assistant must answer from long machine manuals and remember each student's training status between visits. Both are context-and-memory decisions, and each token you keep in context costs budget.

Warm-up 1 min

Recall

In the agent loop, what happens to a tool's result after the program runs the tool?

Check your answer

It goes back to the model, and the loop repeats until the model writes a final answer. Today's question is what the model actually sees each time around that loop.

The context window 3 min

A student asks: "Is the laser cutter free tomorrow, and do I need training?" Trace what the program sends to the model at each step. The model call itself remembers nothing, so the program keeps a list and sends all of it every time:

messages = [student question]                          # call 1 sends 1 item
messages += [model asks check_calendar, calendar result]       # call 2 sends 3 items
messages += [model asks check_training, training result]       # call 3 sends 5 items
# call 4: model reads all 5 items and writes the final answer

Each call re-reads everything before it. Nothing is "remembered" from call 1 to call 2 except what the program put back in the list. If the calendar tool returns 3,000 tokens of bookings, those 3,000 tokens are sent again on calls 3 and 4, and you pay for them each time.

What the model can see in one call has a name: the context window is the set of tokens the model sees when it generates, and it is limited in size (Anthropic, Effective context engineering). What is kept between steps of one run is just that growing list.

Why this works

A model only reads what is in front of it, so "memory" within a run is the program re-sending the transcript. The window is finite, and the same source reports that the model's recall of earlier content gets worse as the window fills, so a bigger pile of old results is not free: it costs money and can hurt accuracy.

Check yourself

An agent makes 10 calls in one run. A tool result of 2,000 tokens arrives after call 2 and stays in the list. In how many calls is that result sent to the model?

Show the answer

Eight calls (3 to 10): every later call re-sends the whole list, so a result that stays in it is paid for each time.

Notes: memory between sessions 2 min

On Monday a student finishes laser-cutter training and the assistant says "great, you're cleared". On Thursday the same student opens a new chat. The program starts with an empty list, so the model has no idea. Now give the assistant a notes file the program stores, for example /memories/students/ana.md:

Monday end: model asks  create /memories/students/ana.md
            "laser cutter: trained 2026-11-09"
Thursday:   model asks  view /memories/students/ana.md   (first thing it does)
            result: "laser cutter: trained 2026-11-09"
            -> model answers: "You're cleared for the laser cutter."

Writing facts to storage outside the window, and reading them back later, is memory in an agent. Anthropic's memory tool works exactly this way: the model asks for file operations and your application carries them out against storage you control (memory tool docs).

Why this works

The window is rebuilt at the start of every session, so only something stored outside it can survive. Memory is just another tool in the loop you already know: the model asks, your code runs it and returns the result.

A common mix-up

"A bigger context window means the assistant remembers students." It is tempting because a long chat feels like remembering. But a window is rebuilt every session; a new chat starts empty however large the window is.

Retrieval: finding the right page 2 min

The laser-cutter manual is 120 pages. A student asks: "What focal-lens height for 3 mm acrylic?" Loading all 120 pages would put them in every call of the run (Figure 1 again). Instead, the assistant has a tool search_manuals(query):

model asks:   search_manuals("focal lens height acrylic 3 mm")
tool returns: [ "Laser cutter manual, sec 4.2, Focus: set height to 6 mm for 3 mm acrylic ..." ]   # about 300 tokens
model answers from that section, citing sec 4.2

The context holds about 300 tokens of the manual instead of tens of thousands. Fetching only the pieces needed, when the model asks for them, is retrieval; Anthropic calls loading data at runtime through tools "just-in-time" retrieval, and notes the trade-off that exploring at runtime is slower than having everything loaded up front (Anthropic).

Why this works

The model needs only the right few paragraphs to answer, and every token in context is re-sent and billed on later calls. Retrieval keeps the window small and focused; the price is one extra tool call, and a wrong search can miss the page.

Check yourself

Your retrieval tool returns a whole 40-page chapter for every question. What is the main problem?

Show the answer

Irrelevant tokens: return small, relevant sections so the window stays focused and cheap.

Worked example and practice 2 min

Worked example

Decide where each fact for the assistant should live: the booking calendar answer, Ana's training status, and the band saw's blade-change steps.

  1. Calendar answer for this question: needed for this run only, so it stays in the context list, and can be dropped after the booking is done.
  2. Ana's training status: needed in future sessions, so it goes in a notes file, read at session start.
  3. Blade-change steps: long, mostly unused, in the manual, so retrieve the one section when asked.

Summary 1 min

  • Context window: what the model sees per call. Within a run, "memory" is the program re-sending the growing list, and you pay for it each call.
  • Notes: facts saved outside the window survive between sessions, written and read through a tool.
  • Retrieval: pull in only the page you need, when you need it, to keep the window small.

Say it in your own words: why can the assistant not remember Ana from Monday without a notes file, even with the largest window?
