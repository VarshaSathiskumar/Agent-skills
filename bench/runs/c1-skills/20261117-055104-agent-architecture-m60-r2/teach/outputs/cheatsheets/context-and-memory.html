Context and memory in an agent

From Lesson 1. Objective O3.

Where does a piece of information live?

Kind of informationLives inCost pattern
Rules needed on every stepInstructions (in the window)Paid every step
Facts that must outlive a sessionNotes in storage, loaded at session startA few tokens per session
Large reference text (manuals)Retrieved: search, then top-k chunks into the windowAbout k chunks per question
Fast-changing facts (bookings)Fetched with a tool when neededOne tool result
Old, re-fetchable tool resultsCleared, with a stubSaves tokens on every later step

Token arithmetic

Tokens read at step n = fixed part (instructions + tools) + question + everything added at steps 1 to n−1. The history is resent in full each call, so total cost grows faster than the number of steps.

Rules of thumb

  • If a fact is not in the request, the model cannot use it.
  • The program is the memory between steps; storage the program owns is the memory between sessions.
  • Keep the smallest set of tokens that still does the job (context rot).
  • Save small, dated notes, never whole transcripts. Notes can go stale.
  • Retrieval quality depends on how chunks are scored and whether chunks keep their context.
