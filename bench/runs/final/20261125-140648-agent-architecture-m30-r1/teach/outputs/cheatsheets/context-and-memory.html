Context and memory in an agent

Cheat sheet for lesson 1, objective O3. Token numbers are illustrative.

The three places, plus one check

PlaceWhat it isWatch out for
Context windowAll text in one call: system prompt, tool definitions, every message and tool result, and the answer. Counted in tokens, and billed.History is resent every step, so cost grows faster than steps. Rot, overflow.
NotesShort facts the program saves outside the window and loads into the next session.Stale or student-written. Label as unverified hints; the id comes from the login.
RetrievalA small index in the window; tools fetch the needed page on demand.Wrong page. Return machine and title; require a citation.
The check (not a place)The program checks the staff record at the moment of use.Never let a note or a retrieved page decide access.

Between steps and between sessions

Between steps, the program resends the history (the API remembers nothing). Between sessions, nothing is resent unless it was saved as a note. Input tokens over a loop: sum of every call, e.g. 600 + 2,100 + 3,600 = 6,300.

When the window fills

Problem or fixIn one line
OverflowInput over the window gives a 400 error. Count tokens before sending.
Context rotRecall gets worse as the window grows, even under the limit. Aim for the smallest set of high-signal tokens.
Clearing old tool resultsReplace bulky old results with one-line stubs. Lossy: look it up again if needed.
CompactionSummarize the history into a new window. Keep goal, decision and next step.

Questions to ask for each fact

Does it change every request (tool call)? Is it big and shared (retrieval, with a citation)? Is it small and personal (a note, as a hint)? Does it decide access (the program's check)?
